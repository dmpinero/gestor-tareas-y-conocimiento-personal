## Specs

User request (verbatim): "quiero poder introducir en los comentarios capturas de pantalla"

Design decided by the parent (assumptions, told to the user before implementation):
- **S1 — Añadir imágenes en el editor.** In the comment editor (`EditorComentario.vue`, used by task, subtask and workflow-step comments) an image can be added by pasting from the clipboard (Ctrl+V of a screenshot), by dropping an image file, and by an "Imagen" toolbar button that opens a file picker. The image is uploaded when added and inserted at the cursor; while uploading the editor shows it is in progress; on error a clear message is shown and nothing is inserted. Keyboard and screen-reader accessible (button with label, alt text: assumption — default alt "Captura de pantalla", editable is not required).
- **S2 — Almacenamiento.** Images are stored in MySQL in a new table (assumption: binary column + media type + size + created timestamp; addressed by an unguessable id, e.g. UUID) so `mysqldump` backups include them. New endpoints: upload (multipart) returns the image URL; download returns the bytes with the stored media type, `X-Content-Type-Options: nosniff` and long cache. Accepted types (assumption): PNG, JPEG, GIF, WebP, verified by content signature, not only by the declared type; max 5 MB each (assumption); other types or larger files are rejected with 422/413 and a Spanish message. Existing endpoints and bodies unchanged; new endpoints documented in OpenAPI.
- **S3 — Saneado (seguridad).** The backend comment sanitizer (`interfaces/api/v1/esquemas/html_comentario.py`) additionally allows `img` with only `src` (and `alt`), where `src` must be a relative URL of this app's image download endpoint (`/api/v1/imagenes/<id>`); any other `img` (external URL, `data:`, `javascript:`, other paths, extra attributes) is removed. Same rule in the frontend DOMPurify allowlist (defense in depth). The visible-text limit (1–500) keeps counting text only; a comment that contains only an image(s) and no text is accepted (assumption) — the blank check treats an allowed `img` as content. The 10000-character HTML limit stays.
- **S4 — Mostrar.** Images render inline in the three comment lists, scaled to the comment width (max height reasonable, e.g. 320 px), and open full size in a new tab or a lightbox on click (assumption: new tab is enough).
- **S5 — Copia de comentarios de pasos.** Copying workflow-step comments to subtasks (existing behavior) keeps the same HTML; copied comments reference the same stored image (no duplication).
- **S6 — Migración.** A new Alembic revision after head `e2c7a9f4b1d6` creates the images table only; no existing data changes. Downgrade drops it.
- **S7 — Docs.** Docs/help mentioning comment formats are updated.

Out of scope (not requested): deleting orphan images, image editing/resizing, galleries.
